# 安全与测试报告

本文档回答三件事：**这个工具把自己的弱点摊开讲**、**它的安全边界在哪**、**它被怎么测过**。

> 快照时间：2026-10-13　·　对应版本：v2.0.0

---

## 一、威胁模型（先讲清楚它是什么）

| 项 | 说明 |
| --- | --- |
| 它做什么 | 用**使用者本人的账号令牌**，调用「词达人」学生端网页版公开的 HTTP 接口，自动完成单词练习 |
| 它不做什么 | 不破解登录、不绕过鉴权、不攻击服务器、不读取他人数据、不修改服务端任何东西 |
| 凭据从哪来 | 只能由使用者本人产生（微信扫码授权，或自己抓自己的包） |
| 数据流向 | 平台接口 ←→ 本机；如配置了大模型/云端 OCR，题目文本或图片会发往**你自己配置的**那个服务 |

## 二、已知脆弱点

按「失效概率」从高到低排列。**这些不是"以后可能有问题"，而是"迟早会出问题"**——因为整个工具的立身之本是平台还没变的那些实现细节。

| 编号 | 脆弱点 | 现象 | 已做的缓解 |
| --- | --- | --- | --- |
| **F1** | **接口域名/路径会搬迁**（已实际发生：`gateway.vocabgo.com` → `app.vocabgo.com`，2026-10 实测老域名 404） | 报 404、`JSONDecodeError` | 授权接口内置多域名**依次兜底**并记住可用域名；全部失败时报明确错误并提示改用抓包 |
| **F2** | **响应混淆方案 `jv` 会新增/调整** | `data` 解出乱码 / 记 `_decode_error` | 全量方案表 + `encode_jv()` 逆运算，可用往返测试快速补新方案 |
| **F3** | **`VERSION` 参数会变**（当前 `2.7.0.260507_01`） | 签名校验不通过 | `version` 可配置；更新时只需改一个常量 |
| **F4** | **题型（`topic_mode`）会新增** | 新题型匹配不上 → 走试答案/大模型兜底 | 策略链末尾有兜底，不至于卡死；未覆盖题型会记为错，下一轮重练 |
| **F5** | **试答案机制依赖服务端回吐 `answer_corrects`** | 该字段消失 → 生词只能靠大模型/盲选 | 策略链让「题库 + 规则 + 大模型」先上，试答案只是兜底 |
| **F6** | **风控是黑盒**：频率、作答轨迹、设备指纹都无公开文档 | 可能被限制或标记 | 默认作答间隔 1.5–3.5 秒、`time_spent` 随机、UA 固定为 PC 微信；**不承诺不被识别** |
| **F7** | **扫码授权依赖第三方授权链路** | 平台关闭该链路 → 扫码不可用 | 保留抓包方案（答题接口与授权接口是两套，互不影响） |
| **F8** | **读图依赖外部能力** | 云端 OCR = 题目图片出本机；本地 tesseract 精度有限 | 默认 `auto`：本地优先；云端需显式配置 |
| **F9** | **GUI 依赖 tkinter，DPI 缩放差异大**（本机 2.33 倍缩放下曾把右侧按钮裁掉） | 布局错位 | 窗口按内容自适应 + DPI 感知（见提交历史里的实测记录） |
| **F10** | **打包 exe 未数字签名**（PyInstaller 通病） | 可能被 Defender/杀软拦或误报 | 提供源码运行方式；发布包不含任何凭据（见第三节） |

## 三、安全与隐私

### 3.1 凭据存在哪、有什么风险

| 凭据 | 存放位置 | 风险 |
| --- | --- | --- |
| 用户令牌 `usertoken` | `config.json` **明文** | 等同于登录态 —— 拿到它就能操作你的账号 |
| 大模型密钥 `llm.key` | `config.json` **明文** | 别人可拿去消耗你的额度 |

**分享给他人之前必须处理**：删掉 `config.json`，或至少清空 `llm.key` 与 `auth.usertoken`。

`build_release.py` 内置**逐字节安检**：打包时扫描 `_internal` 里的二进制在内的全部文件，命中
`sk-…` / `Bearer …` / 长令牌字符串 / 个人配置文件就**中止打包**（除非显式加 `--allow-secrets`）。

实测记录：

```text
=== 安全自检（防止把自己的密钥打进包里）===
  扫描 1099 个文件，✅ 没有密钥 / 令牌 / 个人配置
```

### 3.2 鉴权字段的构成（公开说明）

请求头里有三个字段，其中两个的名字是平台故意起得没意义的：

| 字段 | 构成 | 说明 |
| --- | --- | --- |
| `usertoken` | 随机 32 位 md5 串，由你微信扫码绑定账号 | **唯一真正的凭据** |
| `abc` | `md5(实际发送的 User-Agent)` | 低成本反爬校验：UA 与 abc 必须配套 |
| `authorization-v` | `md5("0")`（提交类接口用 `md5("1")`） | 客户端版本分支标记 |

依据：上游开源实现 `api/request_header.py` 中 `"Abc": encrypt_md5(user_age)`，以及被硬编码的
`cfcd208495d565ef66e7dff9f98764da`（恰为 `md5("0")`）。因此本工具**不需要抓包也能算出来**，
但抓包拿到的真值优先级更高（防止平台升级校验规则）。相关单测：`tests/test_client.py`。

### 3.3 网络出口与代理

`requests` 默认会读取环境变量与 Windows 系统代理。**本工具默认直连并主动忽略它们**（`trust_env = False`），原因有两个：

1. 词达人是国内服务，走代理反而更慢更不稳；
2. 更重要：**凭据不应该经过一个来历不明的本地代理**。

确实需要走代理时，在设置页显式填写，或勾选「跟随系统代理」。

所有网络出口都收在 `vocabgo/net.py` 一个文件里 —— **想审计"它到底连了哪些地方"，看这一个文件就够**。

### 3.4 无遥测

不收集、不上报任何使用数据。除平台接口与你自行配置的大模型 / OCR 服务外，没有其他外部连接。

### 4.2 关键设计：不测真站，但也不是"自欺欺人"

`tests/mock_server.py` 是一个**会较真的假服务端**，它复刻了真实服务端的行为：

- **校验 `sign`**：签名算错直接返回 403（所以签名实现是被真实校验过的）
- **用 `jv` 混淆响应**：随机轮换 `1` / `2_xxxx` / `3_xxxx` 各种方案（所以解码逻辑覆盖了全部分支）
- **模拟「连错两次才给正确答案」**：与线上行为一致（所以试答案链路是被真实语义验证过的）
- **题干图片是真渲染的 PNG**：装了 Pillow 就画真图（所以 OCR 链路能被真 OCR 走通）

它还能单独启动当演练环境：

```bash
python tests/mock_server.py --port 8877
# 另开窗口
set VOCABGO_BASE_URL=http://127.0.0.1:8877 && python -m vocabgo run --kind class --index 0 --fast
```

### 4.3 真机验证记录（均为实际执行过的结果）

| 验证项 | 结果 |
| --- | --- |
| 代理问题的 A/B 实验 | 裸 `requests`（读环境代理）→ `ProxyError`；经 `net.py`（直连）→ **HTTP 200** |
| 客户端真实路径 | `trust_env=False`、`proxies={}`，请求抵达服务器并收到业务响应 |
| 打包 exe 自检 | 关键项全部通过（含 `[通过] 二维码组件可用`） |
| 真机 OCR | 渲染 "abandon" → tesseract → 命中正确选项 |
| 扫码授权实机点击 | 弹出二维码窗口，日志 `📷 二维码已弹出` |
| 发布包凭据扫描 | 1099 个文件逐字节扫描，无密钥/令牌/个人配置 |
| 授权接口实测 | `app.vocabgo.com/Auth/Thirdpart/Authorize` 返回 `code:1` + 有效微信 OAuth 链接 |

### 4.4 没有覆盖到的（诚实清单）

| 未覆盖项 | 原因 |
| --- | --- |
| **真实账号的完整刷题链路** | 需要账号与令牌，不适合放进自动化测试；由使用者首次使用时验证 |
| **风控触发阈值** | 平台黑盒，无任何公开文档，无法量化 |
| **图形验证码** | 只在风控命中时出现，无法稳定复现；已提供 `read_captcha()` 接口 |
| **平台静默修改判定逻辑** | 只能靠使用中发现（表现为正确率骤降） |
| **多平台兼容** | 目前只在 Windows 10/11 + Python 3.14 上验证过 |
