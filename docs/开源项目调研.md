# 词达人（vocabgo）自动答题 · 开源项目调研

调研时间：2026-10-13　方法：GitHub 搜索 + GitHub API 拉取仓库目录树与原始源码 + 交叉验证

---

## 一、结论先放这里

| 项目 | 形态 | 技术栈 | 亮点 | 短板 |
| --- | --- | --- | --- | --- |
| [github123666/cidaren](https://github.com/github123666/cidaren) | 原项目（2023-12 起） | Python + spacy + 打包 exe | 最早跑通全流程；提出 `abc` / `authorization-v` 头；用 OAuth code 免抓包 | 代码组织较乱，题型维护停滞在 2024-03，依赖 spacy 模型 |
| [ularch/Easy_Cidaren](https://github.com/ularch/Easy_Cidaren) | GUI 发行版（原项目魔改） | PyQt/控制台交互 + FiddlerCore | 内置 **token 获取工具**；有日志与任务分数上报；持续追 `jv` 混淆索引 | 1.5.0 起一度闭源、后又开源；本体未公开核心判定细节 |
| [LangQi99/cidaren](https://github.com/LangQi99/cidaren) | 现代重构版 | Python 包 + Flask Web 控制台 | **协议层最完整**：SALT/VERSION/`sign` 签名 + 全量 `JV_RULES` 混淆表；题库 `bank.json` 累积；LLM 兜底；多进程安全题库 | 组词题（mode 32）规则匹配放弃、强依赖 LLM |
| [Rain-shadow/cdr](https://github.com/Rain-shadow/cdr) | 框架化实现 | asyncio + aiohttp + spacy | **扫码授权登录**（二维码）完整链路；验证码走百度 OCR；`词达人答案判定流程.txt` 把判定策略写成 7 级 | 依赖较多（aiohttp/qrcode/spacy）；文档少 |
| [haojiezhe12345/vocabgo-auto](https://github.com/haojiezhe12345/vocabgo-auto) | 极简单文件版 | requests | **试答案法**（连错两次套出正确答案）写得最干净；附带抓包样本 `api/*.json` | 只支持班级任务、无题库、接口版本偏旧（仅 `UserToken`） |

**一句话总结**：这个生态的技术核心只有三件事 —— ①`sign` 签名与响应 `jv` 混淆；②题型（`topic_mode`）的作答格式；
③用「试答案」还是「题库+词义匹配」拿分。我的项目把三者收敛成一套可测试的实现。

## 二、逐个项目拆解

### 1) github123666/cidaren —— 原项目

- 目录：`main.py` + `config/config.json` + `img/`，另有打包 exe。
- 三种取 token 的方法（README 原文）：
  1. 微信 OAuth：在 PC 微信打开
     `https://open.weixin.qq.com/connect/oauth2/authorize?appid=wx2a694105a6abbe6d&redirect_uri=https%3A%2F%2Fapp.vocabgo.com%2Fstudent%2F%3Fauthorize%3D0&response_type=code&scope=snsapi_userinfo&state=STATE`
     然后把地址栏里的 `code=` 填进配置（**code 只能用一次**）。
  2. 自己抓包取 `token`。
  3. B 站流传的付费工具（作者自己评价「不如自己抓包」）。
- 工程细节：`config.json` 里 `token` 与 `code` 二选一；`class_task` / `myself_task` 开关；随机 1–5 秒提交一次答案。
- 已知经验（很有参考价值）：
  - 「加我问问题的人比 star 多」—— 说明这类脚本的用户基数不小；
  - **「模拟器把微信号封了（就刷了一个 xpose 框架）」** —— 模拟器/Xposed 环境风险高；
  - 「不建议一次把自学任务刷完（号被风控，前车之鉴）」；
  - 「一个接口返回两种格式数据」—— 同样是 `data` 字段，明文与 base64 混用，这是 `jv` 机制的雏形；
  - 用 spacy 的 `en_core_web_sm` 做**词形还原**（把 word forms 转原型）来查词义，个别单词转不对就人工过。
- 启示：**词形还原 + 外部词义源**是纯规则路线的必需品；单靠字符串匹配会在变形词上翻车。

### 2) ularch/Easy_Cidaren —— GUI 版与 token 工具

- 结构：`main.py`（12.8 KB）+ `api/` + `answer_questions/` + `decryptencrypt/` + `util/` + `view/` + `en_core_web_sm/`。
- 关键目录 `get token/`：`词达人token获取.exe` + `FiddlerCore4.dll` + `makecert.exe` + `libeay32/ssleay32`，
  即**把 FiddlerCore 包进来做本地 HTTPS 抓包**，用户点一下就能拿到 token。另有 `get token/fetch_token/main.py` 走链接打开的方式。
- 更新日志透露的接口演化情报（很重要）：
  - `2025-11-13 修复 base64 解码异常处理逻辑并更新混淆索引`
  - `2025-11-22 修正 base64 解码异常处理逻辑，调整 3_1024 等异常 jv 的处理方式`
  → 说明 **jv 方案会持续新增/调整**，解码表必须可维护（这也是我把 `JV_RULES` 做成常量表并配套 `encode_jv` 往返测试的原因）。
  - `2026-05-18 添加内置 Token 获取功能并完善日志系统`
- 配置项（与本项目对得上）：`USERTOKEN / ABC / AUTH_V` 三件套，另有 `LLM_URL / LLM_KEY / LLM_MODEL / COURSE_ID / STUDY_GRADE`。

### 3) LangQi99/cidaren —— 协议层最完整的实现

这是含金量最高的一个，`cidaren/a.py`（30 KB）里能直接读到：

```python
SALT = "ajfajfamsnfaflfasakljdlalkflak"
VERSION = "2.7.0.260507_01"
BASE = "https://app.vocabgo.com/studentv1/api"      # 班级任务
STUDENT_BASE = "https://app.vocabgo.com/student/api" # 自学任务
```

- **签名**：`md5("&".join(f"{k}={v}" for k in sorted(params)) + SALT)`，`dict/list` 走紧凑 JSON，空值跳过但 `0` 保留。
- **`JV_RULES` 全表**：`2_1254 / 2_10234 / 2_9214 / 2_9314`（删除字符段）与
  `3_1021 / 3_2265 / 3_2277`（删段后再按 `loc` 做 5 段重排）。这就是本项目 `crypto.py` 的 `JV_RULES` 来源。
- **接口清单**（班级任务）：`PageTask` / `Info` / `ChoseWordList` / `SubmitChoseWord` / `StartAnswer` /
  `VerifyAnswer` / `SubmitAnswerAndSave` / `TaskStudentSignin/Do`；
  （自学任务）：`StudyTask/List` / `StartTask` / `Info` / `ChoseWordList` / `SubmitChoseWord` /
  `StartAnswer` / `VerifyAnswer` / `SubmitAnswerAndSave`。
- **题型处理**：
  - `mode=0` 单词记忆：直接提交，顺手把「单词 → 释义列表」存进 `word_defs`，供后面选择题查表；
  - `mode=11`：题干带 `{word}`，一词多义，直接交给 LLM；
  - `mode=31`：若 `stem.remark` 是 list（带 `relation` 字段）→ **搭配题，多选**，`relation` 就是答案词；
  - `mode=32`：组词题，答案要转成 `in,many,instances` 这种逗号串，规则匹配放弃、交给 LLM。
- **题库指纹**：`f"{mode}::{kind}::{归一化题干}::{remark}::{选项前20字符}"`，与本项目 `topic_key()` 同源思路。
- **工程加分**：`bank.json` 多进程安全（`msvcrt`/`fcntl` 文件锁 + `os.replace` 原子替换 + 锁内二次读盘合并）；
  还有 Flask Web 控制台（`:5000`）做配置中心与任务面板。
- 局限：组词题几乎完全依赖 LLM；网络层没有重试与指数退避。

### 4) Rain-shadow/cdr —— 框架化 + 细节文档

- 目录结构很规范：`cdr/{aio, request, exception, utils, test, config}` + `login.py` + `core.py`。
- **扫码登录链路**（`cdr/login.py`）：本地生成 32 位随机 token → `md5` 混淆 →
  调 `https://gateway.vocabgo.com/Auth/Thirdpart/Authorize`
  （`sign = md5('auth_type=1&return_url=...&timestamp=...&user_token=...&versions=...' + SALT)`）→
  拿 `redirect_url` 画二维码 → 微信扫码 → 轮询 `gateway.vocabgo.com/Student/Main?timestamp=&versions=` 直到 `code==1`。
  本项目的 `tools/qr_login.py` 即按此实现（含终端/PNG 两种呈现与自动写配置）。
- **验证码**：`custom_verification.py` 把二维码/验证码图片 base64 POST 给百度 OCR
  （`ai.baidu.com/aidemo`，`language_type: ENG`），失败返回 `-1` 触发重新生成。
- **`词达人答案判定流程.txt`**：把判定策略写成 7 级优先级（答案库 `example` 键 → 选中词 `mean` →
  以选项自身单词做辅助词查询 → 短语 key 比对 …，并注明「32 过于复杂，暂时搁置」）。这是**题库优先**流派的代表。
- 局限：依赖 aiohttp/qrcode/spacy 等一堆包，用户上手门槛比单文件版高。

### 5) haojiezhe12345/vocabgo-auto —— 试答案法的干净样本

- 整个项目只有 `main.py`（6 KB）+ `api/*.json`（抓包样本）。**只要 `UserToken` 一个头**，说明早期接口鉴权比现在松。
- 核心套路（原文注释）：*「提交第一次错误答案，并获取 topic_code；使用第一次错误作答的 topic_code 提交第二次错误答案，可获得正确答案」*。
- 响应解码：`re.search('ey.*', data)` —— base64(JSON) 一定以 `{"` 开头（`ey`）。遇到解不开就递归剥前缀。
- 多选搭配题：**把每个选项都 verify 一遍**，`answer_result==1` 的收进答案，再统一提交。
- 组词题：`','.join(answer.replace('...','').replace('…','').strip().split())`。
- 局限：无题库、无重试、无自学任务的完整流程；但对**理解「试答案」这条路**价值最高。

## 三、情报汇总（项目里实际用到的）

### 请求侧

| 项 | 值 |
| --- | --- |
| 班级任务 base | `https://app.vocabgo.com/studentv1/api` |
| 自学任务 base | `https://app.vocabgo.com/student/api` |
| 鉴权头 | `usertoken` / `abc` / `authorization-v` |
| 其它头 | `x-requested-with: XMLHttpRequest`、`origin/referer: https://app.vocabgo.com/student/`、PC 微信 UA |
| GET 公共参数 | `timestamp`(ms) / `version` / `app_type=1` |
| POST 公共字段 | 同上 + `sign`，`sign` 与 `app_type` 不参与签名 |
| SALT | `ajfajfamsnfaflfasakljdlalkflak` |
| VERSION（会变） | `2.7.0.260507_01` |
| 渲染参数 | `opt_img_w=2300&opt_font_size=128&opt_font_c=#000000&it_img_w=2702&it_font_size=144` |

### 响应侧

- 统一外壳 `{code, msg?, jv?, data}`，`code==1` 为成功。
- `jv` 决定 `data` 的混淆方式（表见 `vocabgo/crypto.py`）。
- 判题响应关键字段：`answer_result`（1=对）、`answer_corrects`（错够次数后给的正确答案）、
  `over_status`（整题是否判完，多选必用）、`topic_code`（每题一个，需在 verify/submit 之间**串起来传递**）、
  `topic_done_num` / `topic_total`（进度）。

### 题型作答格式

| mode | 提交的 answer |
| --- | --- |
| 0 | 无需 verify，直接 submit |
| 11 / 31 | 选项下标或 `answer_tag`（整数） |
| 31 + remark 为 list | 多个 tag，逐个 verify，`over_status==1` 收工 |
| 32 | 逗号串，如 `in,many,instances` |

### 读图 / 非文本通道（重点核过一遍）

**结论：主力题型没有图片题。** 依据是一份真实抓包样本
（[vocabgo-auto/api/StartAnswer.json](https://github.com/haojiezhe12345/vocabgo-auto/blob/main/api/StartAnswer.json)，
mode=11 真题）：

```json
"stem": { "content": "Researchers are trying to get at the same information through an indirect {route}.",
          "remark": "研究人员正试图通过间接的途径获得相同的信息。",
          "ph_us_url": null, "ph_en_url": null, "au_addr": null },
"options": [ { "content": "noun 道路；航线；路线", "remark": null, "answer": null, "answer_tag": 2,
               "check_code": null, "sub_options": null, "ph_info": null }, ... ],
"sound_mark": "", "ph_en": "", "ph_us": "", "w_lens": [], "w_len": 0, "w_tip": "",
"enable_i": 2, "enable_i_i": 2, "enable_i_o": 2
```

逐条对：

| 现象 | 判定 |
| --- | --- |
| `stem.content` / `options[].content` | **纯文本**，脚本可直接解析，四个开源项目也都只吃文本 |
| 请求参数 `it_img_w` / `it_font_size` / `opt_img_w` / `opt_font_size` / `opt_font_c` | 是「让服务端把题干(item)/选项(option)渲染成图片」的**排版参数**（小程序显示用）。图片是渲染产物，文本照样在 `content` 里 —— 对脚本无害，照原样带上就行 |
| `ph_us_url` / `ph_en_url` / `au_addr` | **音频**通道（英/美发音、听力）。选项是文本，靠选项 + 词义表仍可作答；只有出现「题干仅音频无文字」的题型才需要 ASR |
| `w_lens` / `w_len` / `w_tip` / `sound_mark` / `ph_en` / `ph_us` | 拼写题（补全单词）用的：单词长度数组、提示、音标。属于文本交互 |
| **风控图片验证码** | 这才是真正需要「读图」的地方。cdr 的 `custom_verification.py`：图片为 base64 PNG，POST 到百度 OCR（`language_type: ENG`），失败返回 `-1` 让服务端重出验证码 |

工程结论：**读图不是必需项，但是最便宜的保险**。本项目加了可选读图层 `vocabgo/vision.py`——
按魔数（PNG/JPEG/GIF/WEBP）识别 data-URI / 图片 URL / 裸 base64，命中就 OCR 回文本再进策略链；
后端可换 LLM 视觉 / 本地 tesseract / 自定义回调，结果按哈希缓存；没有 OCR 服务时打警告并照常走 probe，
不影响正确率（mock 里已有对应差分测试：有读图走 match，没有读图走 probe）。

## 四、两条答题流派，本项目的取舍

| 流派 | 代表 | 优点 | 风险 |
| --- | --- | --- | --- |
| **试答案派** | vocabgo-auto、本项目 probe 层 | 正确率接近 100%，不依赖模型/词库 | 服务端能观察到「错两次再对」的异常轨迹；probe 有请求开销 |
| **题库+词义匹配派** | cdr（7 级判定）、LangQi99（bank + LLM） | 轨迹干净、越跑越快、离线可复用 | 首次遇到生词需要 LLM/词库兜底；依赖词形还原质量 |

本项目的取舍：**默认两派都上，但顺序是「题库/规则优先、probe 兜底」**，
并且把 LLM 做成可选、把 probe 做成开关（`--no-probe`）。理由：

1. 题库命中零风险，且能随刷题轮次自我扩张（`--loop` 越刷越干净）；
2. mode=0 天然白送一份「单词→释义」词表，让 mode 11/31 的规则匹配命中率很高（mock 里 5/12 直接命中）；
3. probe 只用来啃生词，且**最终用正确答案重判再提交**，保证落库作答正确、分数不掉；
4. 全部链路可离线复现（`tests/mock_server.py` 校验 sign + 混淆响应 + 两次错答才吐答案），
   协议变更时能在本地先验证再上线。
